# DunjeonLab 학습 가이드

이 문서는 프로젝트 방향, 단계별 학습 주제와 검증 기준이 필요할 때 참고합니다. 일상적인 작업에서는 루트의 `AGENTS.md`만 따릅니다.

## 프로젝트 목적

C#/.NET으로 작은 추격형 던전 게임을 직접 만들면서 자료구조와 알고리즘, 메모리와 GC, 비동기, 스레드와 동기화, 성능 측정을 학습합니다. 기존 던뮬 프로젝트와 분리된 학습용 프로젝트이며, 기능 완성보다 선택 이유와 실제 동작을 설명하는 과정에 중점을 둡니다.

## 게임 방향과 첫 범위

벽이 있는 2D 격자 맵에서 플레이어가 열쇠를 획득한 뒤 출구에 도착하면 승리합니다. 몬스터는 BFS로 플레이어를 추격하며, 플레이어가 잡히면 패배합니다.

- 고정된 격자 맵 하나
- 플레이어 이동과 벽 충돌
- 몬스터 한 종류와 BFS 추격
- 열쇠와 출구
- 승리와 패배 판정

화면은 콘솔 문자 출력 대신 가벼운 2D 그래픽을 사용하는 방향으로 진행합니다. 그래픽은 게임 상태와 규칙을 보여 주는 수단이며, 프레임워크가 게임 루프, 충돌, 경로 탐색과 상태 관리를 대신하게 만들지 않습니다.

## 역할 분담

사용자는 요구사항 해석, 설계와 자료구조 선택, 게임 규칙·게임 루프·이동·BFS의 핵심 구현, 실행 결과 추론과 구술을 담당합니다.

AI는 작은 요구사항과 완료 조건 제시, 설계 질문과 단계적 힌트, 코드 리뷰, 반례와 테스트 시나리오, 측정 방법, 프로젝트 설정과 단순 보일러플레이트를 지원합니다. 컴파일이나 환경 문제처럼 학습 목표와 무관한 장애물은 직접 수정할 수 있습니다. 그래픽 API 호출 순서와 같은 프레임워크 사용법은 평가 대상으로 삼지 않고, 질문과 구술은 자료구조·알고리즘·상태 관리·메모리·비동기·동시성에 집중합니다.

## 진행 절차

1. 요구사항과 완료 조건을 한 단계 분량으로 정합니다.
2. 사용자가 자료구조와 설계를 설명합니다.
3. 사용자가 핵심 코드를 구현합니다.
4. AI가 정확성, 가독성, 복잡도와 선택 이유를 리뷰합니다.
5. 정상·오류·경계 상황을 검증합니다.
6. 필요한 경우에만 성능이나 할당을 측정합니다.
7. 한 번에 하나씩 1분 구술 질문을 진행합니다.
8. 힌트 없이 이해한 부분, 힌트 후 이해한 부분과 복습할 부분을 기록합니다.

## 확장 순서

1. 그래픽 창, 격자 맵, 플레이어 이동과 벽 충돌
2. BFS 방문 처리와 경로 복원, 몬스터 추격
3. 전투, 쿨타임과 상태 효과
4. 여러 봇의 비동기 명령 입력과 취소
5. 동시 아이템 획득과 여러 게임 방
6. 버퍼 재사용, 객체 풀링, GC와 대량 전투 성능 실험

현재 요구사항에 필요하지 않은 구조를 다음 단계의 가능성만으로 미리 구현하지 않습니다.

## 그래픽 도입 원칙

- 렌더링 좌표와 게임의 격자 좌표를 분리합니다.
- 게임 규칙은 그래픽 라이브러리 타입에 의존하지 않게 유지합니다.
- 첫 화면은 색이 있는 사각형만으로 구성하고 이미지, 애니메이션과 사운드는 나중에 추가합니다.
- 창 생성, 입력, 업데이트, 렌더링의 흐름을 사용자가 설명할 수 있어야 합니다.
- 라이브러리의 충돌이나 길 찾기 기능을 사용하지 않고 직접 구현합니다.
- 프레임 속도와 게임 규칙의 진행 속도 분리는 이후 고정 시간 간격 또는 시간 누적 방식으로 실험합니다.

## 동시성 실험

동시성은 실제 공유 상태 문제가 등장한 뒤 도입합니다. 게임 방마다 전용 OS 스레드를 두는 구조를 기본값으로 가정하지 않습니다.

1. 같은 아이템의 중복 지급 문제를 통제된 조건에서 재현합니다.
2. 확인과 상태 변경을 같은 `lock`으로 보호합니다.
3. 명령을 큐에 넣고 게임 방 상태를 단일 실행 흐름에서 변경하는 방식과 비교합니다.
4. 정확성, 구현 복잡성, 대기 시간과 처리량을 비교합니다.

반복 횟수, 동기화 지점, 실행 환경과 측정 방법을 기록하고 한 번의 우연한 결과로 결론 내리지 않습니다.

## 검증과 구술 기준

- 자료구조는 필요한 연산, 데이터 크기, 시간복잡도와 공간복잡도로 설명합니다.
- 값 형식과 참조 형식은 복사, 변경 가능성과 할당에 대한 가정을 확인합니다.
- BFS는 큐, 방문 처리 시점, 이웃 순서, 도달 불가능한 경우와 경로 복원을 검증합니다.
- 맵 경계, 벽, 막힌 경로, 같은 시작점과 목적지 등 관련 경계 상황을 확인합니다.
- 성능 최적화는 측정한 뒤 진행하고 동일한 조건에서 전후를 비교합니다.
- 비동기와 병렬 실행을 구분하고 어떤 실행 흐름이 상태를 변경하는지 설명합니다.

각 단계가 끝나면 요구사항, 선택 이유, 문제가 발생하는 조건, 동작과 효과를 확인한 방법을 사용자의 말로 설명합니다. 용어 설명에 그치면 실제 게임 상태나 구체적인 입력을 기준으로 다시 설명합니다.
